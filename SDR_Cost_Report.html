Executive summary

The SDR agent already has a working Apify integration — this is not a new build. On the Starter plan ($29/mo), using the lead-sourcing actor already wired into the system that returns verified emails, the account can pull roughly 19,000 leads with emails per month before the credit runs out — about 640/day. That's the ceiling on the data-sourcing side. The real bottleneck is elsewhere: the sending pipeline caps every lead at one email per day system-wide, and AI qualification currently processes leads in batches of 5 every 2 minutes — about 150/hour — so a burst of 19,000 fresh leads would take roughly 5.3 days just to get qualified, long before it becomes an outreach bottleneck.

Current pipeline — where cost actually enters

Confirmed from the codebase (ai_sdr_agent/agents/lead_research_agent.py, tasks.py, outreach_agent.py). There is no separate "companies" table — company fields live directly on each lead row.

1
Source leads
Priority order: Apollo.io API → Apify actor → Groq AI-generated fallback. Apify path uses code_crafter/leads-finder ($1.50/1k, returns verified email) or the default apify/google-search-scraper (LinkedIn search results only, no email field).
2
Format-validate
Regex/heuristic check only (lead_validator.py) — flags fake or free-domain addresses, scores 0–100. Not a real deliverability check. $0 cost, runs locally.
3
AI qualification
Groq LLM scores each lead (hot/warm/cold). Batches of 5 leads every 120 seconds, shared queue across the whole platform — not per company. Token usage metered.
4
Enroll in campaign
Manual selection → SDRCampaignEnrollment. No cap found on leads per campaign or per enroll call.
5
Send & track
Per-campaign SMTP. Hard guard: max 1 email per lead per day, system-wide across all campaigns. Bounces detected after send via IMAP reply parsing — not pre-send verification.
⚠ No email verification service is integrated today

The system checks email format (regex) and detects bounces after a send fails — but there is no Hunter.io, NeverBounce, or ZeroBounce-style pre-send verification anywhere in the codebase. The leads-finder Apify actor's own "verified" email field is the closest thing to it currently, and it's actor-side, not ours. Adding real pre-send verification (see §4) would be a new integration.

Reading "how many leads per minute"

0.45 leads/minute is the credit-exhaustion rate if Apify ran continuously all month — not how the system actually behaves. In practice Apify runs happen in batches (current default: 10 leads per scheduled run, one run every 24 hours via the background auto-research job). A single manual run against leads-finder can return hundreds of leads in under two minutes — the $29 credit, not per-minute throughput, is what limits monthly volume.

⚠ Auto-research scheduling gap

Two separate auto-research triggers exist in code — a background thread (middleware.py, every 24h) and a Celery task (tasks.py) — but the active APScheduler job list does not register the Celery version. Only the thread-based path appears to run today. Worth a dev ticket regardless of the Apify decision.

Net effect: qualification throughput (~3,600/day max) comfortably exceeds Apify's own daily ceiling (~644/day at leads-finder pricing), so Apify credit — not internal processing — is the binding constraint on lead volume today.

AI usage cost — what's tracked today

The platform already meters LLM token usage per company per agent (core/api_key_service.py), but it is not broken out by campaign or by lead anywhere in the system. Every SDR sub-agent that calls the model — qualification, outreach personalization, reply/meeting handling — records into the same company-level pool.

07

Billing scenario — Apify credit + real AI enrichment cost

AI cost only applies to the enrichment step — the qualification agent that scores each lead (lead_qualification_agent.py) — not to sourcing or verification. That call runs on Groq's llama-3.1-8b-instant (confirmed in code, no override configured), priced at $0.05/1M input and $0.08/1M output tokens. One qualification call is ~750 input + ~300 output tokens, so real cost is about $0.00006 per lead enriched — not a flat $1. Volume is fixed by the $29 Apify credit either way.

At Groq's real per-token rate, enriching all 19,333 leads costs roughly $1.16 for the whole month — under 4% of the $29 Apify plan itself, and it's covered almost entirely by the platform's free token tier (10,000 free tokens/company) before any paid usage kicks in. The Apify credit — not AI processing — is what actually caps monthly volume and cost. Outreach personalization (a separate Groq call per campaign step actually sent, only when ai_personalize is on) and reply-classification calls add a small amount on top, but at the same sub-cent-per-call rate.
